FIXES FOR THE ORIGINAL SEVEN FINDINGS

1. Global owner access outside HQ
   BranchAccess::isOwner now requires HQ membership and the SystemAdmin role.
   Local account 53 no longer receives global owner access; its stored role and department have not been changed.
   Sources: app/Support/Branch/BranchAccess.php; tests/Feature/Branch/BranchDataAccessRegressionTest.php.

2. Global eiForm application pool
   Backend access requires a central actor with student-list permission. The branch menu follows the same boundary.
   Public application submission remains available.
   Sources: app/Http/Controllers/EiFormController.php; resources/views/layouts/menu.blade.php.

3. Cross-branch stock data through inconsistent ledger rows
   Stock history validates access to the selected product and excludes ledger rows whose centre differs from the product centre.
   Valid HQ cross-branch access and transfer destination display are preserved.
   Source: app/Http/Controllers/ProductController.php.

4. Historical student references and financial documents
   Historical lessons authorize the owning lesson before reading minimal student identity.
   Lessons become read-only when that branch cannot access the student; updates return 409 before changing records or files.
   History GET endpoints no longer save derived dates.
   Receipt export uses issued receipt identity and level.
   Order and receipt printing survives a missing student. Orders use an associated receipt snapshot when available, otherwise an explicit unavailable label.
   Receipt billing fallback is restricted to a contact in the document's branch; stored billing details are preserved.
   Sources: app/Http/Controllers/HistoriesController.php; app/Exports/ExportReciept.php; app/Http/Controllers/OrderController.php; app/Http/Controllers/ReceiptController.php.

5. Recorded teachers who moved branches
   Authorized lessons retain the recorded teacher's display identity.
   Updating the same recorded teacher reference is allowed only for that accessible lesson; selecting a new foreign teacher remains forbidden.
   The edit UI retains the recorded option, clears it between lessons, and explains read-only lessons.
   Sources: app/Support/Branch/BranchRouteAccess.php; resources/views/histories/edit.blade.php; resources/views/histories/script.blade.php.

6. Duplicate identifiers and shared PDF overwrite
   Generated student/product/order/receipt/invoice identifiers skip already issued values.
   Counters and issued values use locking current reads, and the existing locked counter is updated directly.
   Student login rejects an ambiguous code. Student code edits reject another existing code.
   Product lookup reports an ambiguous code instead of choosing a record.
   Receipt-number edits reject collisions in the document's branch while allowing unchanged legacy duplicates.
   PDFs return response bytes without writing a shared number-based file; Unicode filename handling is covered.
   Receipt record updates retry serialization conflicts at most three times. Attachments move after the record transaction commits.
   Sources: app/Support/Branch/BranchNumber.php; ContactController.php; ProductController.php; OrderController.php; ReceiptController.php.

7. Book receipt summaries after student transfer
   Student-list book summaries use the scoped Order query, matching the detail query.
   Destination branches count their own orders; the HQ owner retains authorized historical totals.
   Source: app/Http/Controllers/ContactController.php; tests/Feature/Branch/BranchBookSummaryTest.php.
